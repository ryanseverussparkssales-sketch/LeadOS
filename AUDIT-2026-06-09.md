# LeadOS Repo Audit — 2026-06-09

Triage-depth audit of `leadosuite-mvp` (446 source files, ~55k LOC, 237 API routes).
Covers silent-failure bugs, security, correctness/types, and dead code/deps.
Critical and high-severity items have been **fixed and committed** (see "Fixed" tags);
the rest is a prioritized backlog.

Overall the codebase is in better shape than the schema-drift incidents suggested.
Auth coverage is strong (all 237 routes checked; the 20 without `requireAuth` are
legitimate webhook/cron/public-token exceptions). Webhook signatures (Twilio, Stripe,
Resend) are properly verified. The real risks were a handful of missing **ownership**
checks (supabaseAdmin bypasses RLS, so tenant isolation lives entirely in code).

## CRITICAL — ✅ Fixed

### C1. Credentialed SSRF / cross-tenant recording access — `api/calls/recording-proxy`
The route accepted any caller-supplied `?url=` that merely *contained* `twilio.com`
and fetched it with the **master** `TWILIO_ACCOUNT_SID`/`AUTH_TOKEN`. Any logged-in
user could read every tenant's call recordings, and hit arbitrary Twilio REST
endpoints (e.g. enumerate all recordings account-wide). The route had **no callers**
in the frontend — it was dead but publicly reachable.
**Fix:** rewritten to accept only a `call_id`, resolve the recording URL from a row
scoped to the caller (`.eq('user_id', ownerId)`), and hard-validate the host ends in
`twilio.com`. Mirrors the already-correct `api/calls/recording`.

## HIGH — ✅ Fixed

### H1. IDOR on `api/campaigns/[id]/sdrs` (GET/POST/DELETE)
No ownership check on the campaign id. Any user could list another tenant's SDR
assignments (leaking team-member emails), assign SDRs into, or remove SDRs from, any
campaign. **Fix:** added `verifyCampaignOwner()` (same helper pattern as the parent
`campaigns/[id]` route) to all three handlers.

### H2. IDOR on `api/tags/[id]` DELETE
The handler deleted `contact_tag_mappings` by `tag_id` **before** the ownership-scoped
tag delete. Passing another tenant's `tag_id` stripped that tag from all the victim's
contacts (the scoped second delete was a harmless no-op). **Fix:** verify the tag
belongs to the caller (404 if not) before touching mappings.

### H3. Quotas race condition — `lib/server/quotas.ts`
`incrementQuota` is read-modify-write (`current_value = (old) + amount`), so concurrent
calls clobber each other → under-counted quotas. Flagged with a standing TODO in the
code. **Fix (recommended, not yet applied — needs a DB function):** add a Supabase RPC
`increment_quota(quota_id, amount)` doing `UPDATE quotas SET current_value =
current_value + $amount WHERE id = $1` atomically, and call it instead of the JS add.
Low urgency at current volume but it's real data drift.

## LOW / Cleanup — Backlog

- **Dead code:** `recording-proxy` (now secured but still unused), and orphaned
  components `DialButtonPicker.svelte`, `LazyWidget.svelte`, `Skeleton.svelte`
  (zero imports) — safe to delete.
- **Unused dependency:** `groq-sdk` — zero imports (Groq is called via raw `fetch`).
  Remove from package.json.
- **45 `svelte-check` type errors** (pre-existing, non-blocking — Vercel's esbuild
  build doesn't type-check). Mostly possibly-null access and supabase generic-type
  mismatches. Worth burning down for editor sanity but no runtime impact. Today's
  touched files are all clean.
- **SQL sprawl:** 66 `.sql` files, 64 ungoverned at repo root (multiple
  "RUN-ALL-PENDING" snapshots, `COMPLETE-SCHEMA` vs `schema` vs `setup`). No ordered
  migration history. **This is the root cause of the schema-drift bug class.** Adopt
  `supabase/migrations/NNNN_*.sql` as the single source of truth; archive the rest.
- **2 real TODOs:** quotas race (H3 above) and unimplemented Spotify OAuth
  (`SpotifyWidget.svelte`). Package name is still `rogueos-mvp` (cosmetic).
- **4 DB tables never referenced by code:** `asset_shares`, `cron_logs`,
  `dialer_activity`, `user_sessions` — confirm intentional before cleanup.

## What's healthy (verified, no action)

- **Auth:** 237/237 routes checked; all unauthenticated ones are webhooks (signature-
  verified), cron (CRON_SECRET), super-admin (`requireSuperAdmin`), or public token/share.
- **Webhook signatures:** Twilio (`validateRequest`, fail-closed), Stripe (HMAC +
  `timingSafeEqual`), Resend (svix HMAC) all verified.
- **Secrets:** vault routes decrypt only for the authenticated owner; no token/secret
  leakage to clients found.
- **Most ownership checks:** ~45 `[id]` mutation routes spot-read — the overwhelming
  majority correctly scope by `user_id`/owner. The 3 fixed above were the exceptions.

## Top recommendations (in priority order)

1. **Migration discipline** — the 66-file SQL sprawl caused every schema-drift bug.
   Move to ordered `supabase/migrations/`. Highest long-term ROI.
2. **Stop discarding supabase errors** — a lint rule + a thin `mustInsert()` helper
   would have surfaced all of today's failures at write time.
3. Burn down the 45 type errors and delete the dead code/dep listed above.
4. Apply the quotas RPC (H3) before call volume grows.
